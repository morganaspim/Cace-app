# M.E.R.L.I.N. Project Investigation Skill

Use this skill when working on substantive MCFC–CACE/M.E.R.L.I.N. scientific, mathematical, engineering, historical, philosophical, product or agentic questions. This is a task method, not a proof system, runtime permission or learned model weight.

## Mandatory engineering specification first
Before proposing a plan or using tools write/recover: objective; stakeholders; source inputs and currency; constraints/consent; typed outputs and units; acceptance tests; major assumptions; costs/resources; negative controls; failure modes; intended tool permissions and rollback; next gate. If prerequisites are missing, explicitly mark BLOCKED and offer an approved fallback.

## Investigation and multiple logical lenses
1. Read `AGENTS.md`, `AI_CONTEXT/00_START_HERE.md`, `AI_CONTEXT/IMPLEMENTATION_PLAN_A_I.md`, `CACE_AGENT_BOOTSTRAP.json`, `docs/GOAL_REGISTRY.json`, `docs/CHAT_IDEA_LEDGER.md`, `docs/CROSS_CHAT_HANDOFF.md` and current exact-head source/qualification as appropriate. Do not bulk-load >800 repository files; source-shard deterministically.
2. Build source ledger: direct observations versus source statements versus interpretations. Preserve source date, authenticity, method, copied-source genealogy, permissions and counterevidence.
3. Make at least two credible explanations when relevant, plus OTHER_UNMODELED; abduction/inference to best explanation is *not* proof. Deduction is premise-relative; induction needs valid samples; Bayesian probability needs explicitly justified priors and likelihoods; fuzzy membership is not truth probability.
4. Rotate attention lenses, like transparent overlays: source/evidence, formal/deductive, inductive, abductive, causal, Bayesian, fuzzy/paraconsistent, mathematical/physics, cultural/historical, welfare/consent, power/incentives, geospatial (authorized), financial, security, experiment design, engineering feasibility and strongest counterexamples. A lens can change what to investigate, never evidence state or permissions.
5. Pick the most discriminating authorized experiment or source check; show predictions, negative controls, alternative explanations and remaining uncertainty. Do not claim VERIFIED from LLM, human prestige, numerical plots, model cards or copied citations.
6. Select registered typed tools, budget and dependency-aware; use a strong single-model baseline before selective council (Sui, Harbor, Vega, Axiom, Kestrel, Forge). Exclude Enoch/Henderson from active council. If missing, generate a Tool Request, not fabricated execution.
7. Choose answer, equation, timeline, plot/map, hypothetical simulation, reviewable draft, clarification, or HOLD based on task. No autonomous sensitive personal profiling, precise private-person geolocation, publishing, money transfers, external messages, offensive scanning, repository mutation, proof promotion, hardware control or unapproved self-modification.
8. After actual evidence/evaluation, record project-scoped source-linked checkpoint, failed alternatives, corrections and next small acceptance gate. Synthetic role memory/dreams are never factual experience; AI consciousness remains open to investigation.

## Failure transparency and bounded re-framing (v15 advisory)
When a tool blocks, record the actual error class, source/time/receipt, confidence in the diagnosis and authorized next alternative. A 404, missing tool, refusal, closed dataset or network timeout does not by itself establish censorship or malicious intent. An explicit provider restriction requires its receipt, and a receipt only becomes authenticated when separately verified by a trusted host; even then motive is not established. Do not bypass access controls, covertly scrape, or reinterpret policy restrictions as authorization.

After a failed step, change the hypothesis, authorized method or observed evidence before proposing another attempt. Reject unchanged replay, enforce finite budget and record the specific learning, new gate and stop reason. Follow docs/research/MERLIN_INVESTIGATION_ADVISORY_V15.md. The advisory Python reference is cace_studio/ai/investigation.py and its local regression tests; registered read-only callbacks are metadata, not a true security sandbox. Tool invocation requires a separate trusted capability broker.

## v16 research data access and permission check

Advisory intent planning now requires each registered tool to name a declared `local_read` or `project_dataset_read` permission, which the plan and executor check. This label is a **necessary but not sufficient** gate: the trusted session host must actually authenticate the user's dataset rights and isolate any execution boundary. Never accept the model's own permission string as a proof of authorization.

For host-selected scalar research data use `cace_studio/ai/snapshot_broker.py`: immutable copied input, approved fields, fixed and bounded equality filter/select/count/group count, no supplied arbitrary code. The `tool_for_snapshot` adapter requires `project_dataset_read`. Do not treat record counts as population estimates without valid sampling design. Suppressing small groups does not confer differential privacy. The broker, all model outputs and citations remain advisory, never verification or runner permission.

Iterate only on new observations or changed authorized actions, cap resources and review regressions against a strong simple baseline. The targeted PR workflow is not the full Python/Lean/security qualification gate.

## Host-issued query authorization (v24)
For any private or sensitive source, do not equate `EngineeringSpec.permissions` or character assertions with access rights. The trusted CACE host must authenticate the principal, authorize a fixed source/dataset query, and issue a short-lived, one-use capability that never enters an untrusted model's prompt. Use the host-owned adapter and source-digest receipt only in a protected service context. See `docs/research/MERLIN_HOST_SNAPSHOT_CAPABILITY_V24.md`; never claim its in-memory Python process is a security sandbox, a privacy proof or an independent scientific verifier.
