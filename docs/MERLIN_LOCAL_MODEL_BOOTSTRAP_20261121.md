# Fixed local coding provider bootstrap

This is the fixed bootstrap profile for the user-selected `cace-oci-a1` host. It installs an independent numeric-loopback model service and records an actual bounded coding smoke. It does not edit the private Merlin service, register a model as qualified, merge a product branch, or grant autonomous deployment authority. External model/API spending is zero; it uses the existing Oracle host.

## Observed prerequisites and exact inputs

The retained context inventory run `44911240134`, attempt 1, observed Oracle Linux 9.8, aarch64, two CPUs, 9,635,400 KiB available RAM, and 104,440,762,368 free disk bytes. Its known-path/runtime checks found no installed configured local model. These are a dated observation, and bootstrap rechecks minimum headroom and fixed paths before starting.

The first bootstrap run, `44913064061` attempt 1, passed all 29 controller controls but stopped in preflight because this image provides `/etc/os-release` without `/usr/lib/os-release`. Unsupported links are rejected. The failed attempt remains retained; a new execution requires a separately reviewed request and still encounters the unchanged pending-intent guard.

The corrected run, `44913427137` attempt 1, passed all 32 controller controls and downloaded the exact source archive, then stopped before the first extracted file because GitHub's archive uses regular-file modes `0664` and `0775`. Artifact `14710937033` retains that failure (`archive mode or size`) and its completed phase `intent-recorded`. The repair accepts those two known representations and removes group-write permission, yielding `0644` and `0755` while preserving Git executable identity. Directory mode `0775` is similarly restricted to `0755`. No other archive type, mode, path or resource limit is relaxed. Before a recovery request, the entire retained pinned archive is extracted locally and every source byte identity and executable mode is compared with the verified upstream Git tree; no upstream source is executed in that check.

## Fixed execution and resource contract

The existing `.github/workflows/merlin-dot-oci-operations.yml` entry point is specialized on branch `merlin/dot-ops/model-bootstrap-20261121`. A trigger commit must add exactly one `merlin/model-requests/<canonical-uuid>.json` with exactly `schema`, `request_id`, `operation`, and `created_at`. The schema is `merlin-model-bootstrap-request/1`; operations are `bootstrap`, read-only `inspect`, and the single fixed `recover_source_permissions` case described below. No caller-selected URL, path, program, prompt, model, recovery target or resource setting is accepted. The runner/repository/ref, first run attempt, controller Git blob and SHA-256, tests, and request filename are verified before the root invocation. The workflow runs the exact focused synthetic controls first.

The source build uses observed `/home/opc/.local/bin/cmake`, GCC/G++ and two build jobs as `opc`. Its transient systemd unit has private networking, a 4 GiB memory cap, zero swap, 150% CPU quota, 32 tasks, and a 1,800-second runtime limit. The child verifies actual cgroup-v2 values. PID 1 opens fixed stdin/stdout/stderr files; `--pipe` is deliberately absent because this host previously rejected descriptor passing. Each log is monitored at 1 MiB with a bounded retained prefix; the process-wide 256 MiB file-size limit also accommodates compiler object/binary outputs. The log monitor is a supervisor check, not an atomic 1 MiB kernel file limit. No SELinux setting changes.

`BUILD_SHARED_LIBS=OFF` and `GGML_BACKEND_DL=OFF` keep the built llama/ggml code in the recorded executable. Cache flags are checked, and `readelf` records and restricts `DT_NEEDED` to the expected host system libraries. The binary's actual hash and version output are recorded after native build. Host system libraries are outside this bounded artifact identity claim.

The independent `merlin-model-provider.service` runs as new unprivileged `merlin-model`, with an empty explicit environment, literal `127.0.0.1:8080`, alias `merlin-qwen-coder-1.5b-q4`, one parallel slot, two compute threads, a 4,096-token context, zero GPU layers, offline mode, and no web UI. Its runtime caps are 3 GiB memory, zero swap, 150% CPU and 32 tasks. It remains outside the private daemon's AF_UNIX/private-network namespace. The bootstrap checks actual UID, executable, exact argv, current host network namespace, cgroup limits, and the expected model file's device/inode mapping before accepting the provider.

## Acceptance, retained evidence and rollback

The root-owned install is versioned under `/opt/merlin-model-provider/releases/<content-identity>/`. Startup must report health and the exact model alias. The fixed public clamp-function smoke first posts the identical chat body to `/v1/chat/completions/input_tokens`, checks template-inclusive count plus 384 output tokens against 4,096, then issues exactly one plain chat inference request. Actual token usage must equal the count and remain within budget. The generated function is interpreted through a restricted AST with twelve independent numeric cases; it is never executed as Python or a shell command. Raw request/count/response and exact hashes are retained, including failures.

The service is then restarted. Acceptance requires a changed main PID, the same installed binary/model/unit identities and limits, and unchanged observations of the preexisting private Merlin service/config/current release. Success writes `/etc/merlin-model-provider/bootstrap-receipt.json` (schema `merlin-local-model-bootstrap-receipt/1`, at most 64 KiB), followed by `/etc/merlin-model-provider/manifest.json` (schema `merlin-local-model-provider/1`, at most 16 KiB). The manifest binds the receipt digest and revision `gguf:<model-sha256>;llama:<source-commit>;bin:<binary-sha256>`. It retains `qualification:false` and `promotion_authority:false`.

A durable host bootstrap intent is written before acquisition or installation. An interrupted or failed intent is not authority to repeat model inference or installation. A duplicate completed request performs current read-only inspection. Any fresh or stale conflicting bootstrap request fails closed. This host deployment intent is separate from product task/session receipts; the product still uses its existing canonical artifact store and explicit host authentication when it admits the provider records.

The explicit source-permission recovery is pinned only to run `44913427137`, its exact original request and controller, failure receipt SHA-256 `16e99a0536de6ef609f8122dbf34fd57148aa1dc36d4c30913c1c766ceefa3a0`, and expected original intent SHA-256 `24e28ad922512260981fd64aed982c46fb856c2c2cb6e26d3a01668a781e2432`. The latter is derived from the exact retained failed receipt and the original controller's deterministic intent formula; recovery must verify the actual root-owned intent bytes before it has authority to proceed. The original attempt must contain only that failure receipt, the hash-verified source archive and an empty source directory. Fresh preflight must still find the provider service, configuration, install root, dedicated user/group and listening endpoint absent, and the old private-service and OS observations unchanged. A new request, workflow commit, controller and run are required. Ordinary `bootstrap` never crosses the pending-intent guard.

Before extraction or build, recovery writes an immutable root-only linked record at `/var/lib/merlin-model-bootstrap/source-permissions-recovery-44913427137.json` and retains its readable copy in the new run. It preserves the original intent, failure and archive, reuses that verified source download, and extracts into a new run directory. An interruption after either recovery intent or inference response remains fenced; a later request cannot restart it automatically. A duplicate completed recovery must match its exact request, completed receipt and recovery-record digest before performing current read-only inspection. The record makes no inference, qualification or deployment claim by itself.

On ordinary failure after installation, rollback verifies the exact created unit before stopping/disabling/removing it and restores the previous absent service. Bounded candidate files, the dedicated unprivileged identity, and attempt evidence remain for review. Partial installation before a complete install result is recorded as uncertain and is not automatically retried or claimed to be fully cleaned up. An abrupt supervisor/host interruption may require explicit host reconciliation. No unrelated service, private state, SELinux policy or existing configuration is altered as rollback.

The bootstrap artifact contains only bounded receipt/log/smoke files. It does not include model weights, build source, executables or a private-state snapshot. A passing smoke is operational evidence for this exact tiny task; it is not a general coding benchmark, model-quality improvement, independent model verification, or production qualification. The subsequent real research episode and user-route acceptance remain separate release gates.
